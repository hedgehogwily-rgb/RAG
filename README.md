# RAG mini-product

Учебный RAG: документы из `knowledge_base/` режутся на чанки, эмбеддятся и кладутся в Weaviate. На вопрос сервис ищет ближайшие чанки и просит модель ответить только по ним. Если поиск слабый, ответ — «В базе знаний этого нет.»

## Структура

- `knowledge_base/` — текстовые документы
- `src/` — загрузка, чанки, эмбеддинги, Weaviate, поиск, генерация
- `main.py` — полный прогон: индексация, поиск, сравнение ответов с retrieval и без
- `app.py` — FastAPI: индексация и вопрос-ответ
- `docker-compose.yml` — локальный Weaviate

## Как поднять Weaviate

Нужны Docker и свободные порты `8080` и `50051`.

```bash
docker compose up -d
```

Проверка: `curl http://localhost:8080/v1/.well-known/ready` отвечает `200`.

## Как подготовить базу знаний

Положите файлы `.txt` в `knowledge_base/`. В репозитории уже есть 9 документов про RAG. Загрузчик читает только `*.txt`, сжимает лишние пробелы и пустые строки.

## Как загрузить чанки в Weaviate

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

В `.env` впишите ключ без кавычек:

```text
OPENAI_API_KEY=sk-your-key-here
```

Индексация через API:

```bash
uvicorn app:app --reload
curl -X POST http://127.0.0.1:8000/index
```

Ответ содержит число документов, чанков и объектов в Weaviate. Повторный вызов обновляет те же чанки и удаляет устаревшие.

Полный учебный прогон, вместе с печатью чанков и сравнением ответов:

```bash
python main.py
```

## Как задавать вопросы

Демо-вопросы:

```bash
curl http://127.0.0.1:8000/demo-questions
```

Один вопрос:

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H 'Content-Type: application/json' \
  -d '{"question": "Зачем нужен overlap при разбиении текста на чанки?"}'
```

Поля ответа:

- `answer` — текст для пользователя
- `sources` — чанки, на которых стоит ответ
- `context` — эти же чанки так, как их увидела модель
- `best_score` — близость лучшего чанка, от 0 до 1
- `weak_retrieval` — `true`, если лучший score ниже `0.40` и модель не вызывалась

Если индекс пуст, `POST /ask` отвечает `409`. Состояние базы: `GET /health`.

## Как читать sources

Строка `rag_overview.txt#0` — файл `knowledge_base/rag_overview.txt`, чанк с `chunk_id` 0. Несколько источников перечисляются через запятую и в `answer`, и в поле `sources`.

Если `weak_retrieval` равен `true`, `sources` пустой, а `answer` равен «В базе знаний этого нет.» Поиск что-то вернул, но лучший чанк слишком далёк от вопроса, и этот контекст модели не отдаётся.

Если score порог прошёл, но в чанках нет ответа, модель сама пишет ту же фразу. Тогда `sources` тоже пустой: на отказ источники не вешаются.

## Примеры

Пять вопросов к уже проиндексированной базе. Ответы сокращены до сути.

**Что такое RAG и зачем нужна внешняя база знаний?**  
`best_score` 0.575, источники `rag_overview.txt#0`, `prompt_engineering.txt#0`, `llm_basics.txt#0`.  
Ответ: RAG дополняет языковую модель внешней базой знаний, чтобы перед генерацией искать фрагменты документов и меньше галлюцинировать.

**Зачем нужен overlap при разбиении текста на чанки?**  
`best_score` 0.643, источники `rag_pipeline_long.txt#1`, `chunking.txt#0`, `rag_pipeline_long.txt#2`.  
Ответ: overlap не обрывает мысль на границе чанка, конец одного фрагмента повторяется в начале следующего.

**Чем embeddings отличаются от обычного ключевого поиска?**  
`best_score` 0.449, порог пройден, но в найденных чанках нет этого сравнения.  
Ответ: «В базе знаний этого нет.», `sources` пустой.

**Для чего используют векторные базы данных вроде Weaviate?**  
`best_score` 0.539, источник `vector_databases.txt#0` и соседние чанки пайплайна.  
Ответ: они хранят эмбеддинги и ищут ближайших соседей по косинусному расстоянию.

**Как оценивать качество retrieval в RAG-системе?**  
`best_score` 0.734, источники `rag_overview.txt#0`, `evaluation.txt#0`, `retrieval.txt#0`.  
Ответ: faithfulness, relevance, answer correctness; метрики RAGAS, ручная оценка и A/B-тесты.

Вопрос вне базы, «Какая столица Франции?»: `best_score` около 0.004, `weak_retrieval` true, ответ «В базе знаний этого нет.»
